# lurra

Go 1.27 todo app template: chi + httplog/slog API, SQLite (ncruces driver, goose migrations),
swag → OpenAPI → `web/src/lib/api/schema.ts`, Svelte 5 SPA embedded in the binary.

## Layout

- `cmd/app`: wiring only. `internal/`: one package per concern (config, logging, server, api
  handlers, httpx, model, store); SQL migrations live with the store.
- `web/`: Svelte 5 + Vite SPA, no SvelteKit; `web/*.go` serves its `dist/`. Pages in
  `src/routes/` (routed by sv-router in `src/lib/router.ts`), shared code in `src/lib/` (the one
  API client in `api/`, state as `*.svelte.ts` modules), own components in
  `src/lib/components/`, shared test helpers and fixtures in `src/lib/test/`. Reuse what's there
  (e.g. menus build on the existing dropdown components) before adding new.
- `.github/workflows/`: `ci.yml` runs each `make ci` target as its own job (plus `docker`, CI
  only) and a `ci` job that passes when all do; `security.yml` runs `make security`. Scripts
  the workflows run (job summaries) live in `.github/scripts/`, not inline.

## Workflow

- Answer questions and wait; edit files only after an explicit go-ahead.
- Run the checks for what you touched: `make check-go test-go` (Go), `make check-web test-web`
  (`web/`), `make ci` for Makefile, Docker or tooling changes. Docs (`*.md`) need none. Fix all
  failures.
- Never run `docker build`, containers or the app to verify; the user does that.
- Run `make bindings` after changing API annotations or request/response types.
  `web/src/lib/api/schema.ts` is generated; never edit it by hand.
- Import shared code in `web/src/` through `$lib/...` and pages through `$routes/...`, never
  `../`; only files in the same folder use `./`.
- Translations: every user-visible string in `web/` (text, labels, placeholders, `aria-label`,
  `title`, error messages) goes in `web/messages/en.json` and is used as `m.key()` (never
  `m[key]`); no hardcoded display text, except brand names (`lurra`). Call `m.key()` in markup
  or `$derived`, never in a plain `const`: the locale switches live (`$lib/i18n.svelte.ts`), and
  a `const` won't update.
  `web/src/lib/paraglide/` is generated by `npm run i18n:compile` (and Vite); never edit it.
  Check with `make check-i18n` (strict, part of `make ci`: no PR merges untranslated).
- Fix formatting with `make format` (gofmt and Prettier); the checks only report it.
- UI is daisyUI (Tailwind plugin, classes only; use the daisyui skill): plain HTML with daisyUI
  classes and theme colors (`bg-base-100`, `text-base-content`), no `dark:` and no UI component
  library.
- Run `make tidy` (not just `go mod tidy`) after dependency changes.
- A target added to or removed from `make ci` is also added to or removed from the matrix in
  `.github/workflows/ci.yml`, and the other way round.
- Go tools go in `tools.mod`. One that conflicts there runs with `go run pkg@version`, its version
  in a Makefile variable under a `# renovate: datasource=go depName=…` comment. Actions are pinned
  by commit SHA with the version as a comment (`@<sha> # v7.0.1`).
- Prefer the simplest option; keep Makefile targets few (private helpers start with `_`).
- Don't repeat logic: when a change would copy behavior that already exists (a component, a
  helper, a test setup), propose extracting it into one shared place, and ask before doing it.
- Keep this file current: when a new rule, convention or repeated correction appears, propose
  adding it here, in as few words as possible. When a new tool, check or convention is added,
  also propose the audit check that keeps it in shape (see Audits).

## Rules

- Coverage target is 100% (checked by `make test-go`). New Go code ships with tests; when a
  branch isn't worth a test (near-impossible or too costly), mark it `// coverage-ignore: <reason>`.
  Plain `if err != nil { return ..., err }` bodies are excluded automatically.
- Web coverage is also 100% (Vitest, `make test-web`). Tests sit next to the code as
  `*.test.ts` (Testing Library); skip a branch with `/* v8 ignore next -- <reason> */`.
  Generated code, `main.ts` and test helpers are excluded (the list is in `vite.config.ts`).
- Test behavior, not just lines: new features get tests for their intended behavior and edge
  cases, and bug fixes get a regression test, even when coverage is already 100%.
- New packages need tests or an exclude in `.testcoverage.yml`.
- Never edit an applied migration; add a new `NNNNN_name.sql` with Up and Down sections.
- New domain errors need a case in `api.writeError`, otherwise they become a 500. If their status
  is shared with another error, give them an error code (`httpx.WithErrorCode`, plus the `enums`
  tag on `HTTPError.ErrorCode`) and a translation in `ApiErrorAlert.svelte`.
- Log with `slog.*Context(ctx, ...)` so lines carry `request_id`.
- New Go source dirs must be added to the Dockerfile's explicit `COPY` lines.

## Audits

When asked for an audit, change nothing: read (never install, format or delete), then report
findings grouped as *should fix*, *needs a decision* and *optional*, plus what was checked and
found fine, and wait for which ones to fix. Also report anything the audit found that this list
doesn't cover yet, with the check to add. Run `make ci` first; then check:

- **Dependencies:** every npm, `go.mod` and `tools.mod` entry is used (code, config, scripts,
  Makefile); nothing is duplicated or in the wrong section (all npm deps are dev); `npm ls` and
  the lockfiles agree; `make security` advisories are known.
- **Leftovers:** dead files, empty dirs, unused exports or components, commented-out code,
  `TODO`/`FIXME`, demo content, config or comments for removed tools. Look in every tracked
  file, not just source: the Dockerfile, Makefile and configs too.
- **Generated code:** only in its known places (`schema.ts`, `src/lib/paraglide/`, `dist/`),
  ignored by Prettier, ESLint, coverage and `.dockerignore`, untracked unless meant to be.
- **Consistency:** the same thing is named and done the same way everywhere (imports via `$lib`,
  messages via `m.key()`, theme colors, test style, comment style, file names); every path in a
  config, comment or doc exists; the Makefile summary, `make help` and `.PHONY` list the same
  targets; `make ci` and the `ci.yml` matrix list the same targets; the Dockerfile copies every
  Go dir; workflow actions are pinned by SHA.
- **Config:** no dead or duplicated settings (aliases, excludes, ignores), each setting in the one
  place that reads it, and comments that match what the setting does.
- **Up to date:** every tool's config (tsconfig, ESLint, Vitest, golangci-lint, Prettier, Vite,
  Renovate, …) uses the current recommended presets, rules and options for the installed
  versions; nothing deprecated, nothing newer missing.
- **Duplication:** any repeated code (components, helpers, test setups, config) goes under
  *should fix*, with where to extract it.
- **Docs:** `CLAUDE.md`, `todo.md` and code comments describe the code as it is now.
- **Tests:** behavior is tested, not just lines; every coverage exclude and ignore comment still
  has a valid reason; no skipped tests or leftover debug output.
- **Git:** no tracked file that should be ignored, nothing ignored that should be tracked.
